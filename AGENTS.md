# Movie Archive — guide for coding agents

Electron app for Windows. It catalogs movies, series and anime kept in folders on several hard drives,
identifies each title from its **folder name**, and fills in poster, plot and details from OMDb
(Jikan/MyAnimeList as the anime fallback). UI is Persian (RTL) and English (LTR). The owner speaks Persian:
answer him in Persian, keep code and comments in English.

Specs (Persian, the authority): `docs/superpowers/specs/2026-11-17-movie-archive-design.md` (v1) and
`docs/superpowers/specs/2026-11-18-series-translation-design.md` (v2: recursive scan, series, translation, tabs; wins where it differs).
Plans: `docs/superpowers/plans/2026-11-17-movie-archive.md`, `docs/superpowers/plans/2026-11-18-series-translation.md`.

## Commands

- `npm test` — `node --test`, no network, no Electron needed. Run it before every commit.
- `npm start` — run the app (needs Electron; under Linux use `xvfb-run -a npx electron --no-sandbox .`).
- `npm run dist` — Windows installer in `dist/` (run on Windows).

## Layout

- `src/core/*.js` — all logic, plain CommonJS. I/O (`fetch`, `fs`, PowerShell) is passed in, so tests use fakes.
  `pattern` folder-name parser · `scanner` read-only recursive scan · `sync` scan → DB · `drives` drive serials ·
  `omdb`/`jikan` providers · `cache` stored API answers (`cache` table, `searchCached`) · `match` `pickConfident` (auto-pick of a search hit) ·
  `pipeline` matching queue · `episodes` season/episode queue · `translate` MyMemory + stored translations ·
  `fix` Online Info Fix · `library`/`search` entries, tabs, genre filter, sort, fuzzy search.
- `src/api.js` — wires core modules into one object. `src/main.js` + `src/preload.js` only expose it over IPC.
- `src/renderer/` — vanilla HTML/JS, `i18n.js` holds both languages (keys must match; `test/i18n.test.js` checks).
  UI: no framework, no build. Light/dark tokens live in `styles.css` (`:root` light, dark via `prefers-color-scheme` and `[data-theme]`); `theme.js` (loaded in `<head>`) applies/saves the choice in localStorage. Font Vazirmatn is bundled in `renderer/fonts` (OFL). CSP forbids inline styles, so set dynamic values with `el.style.setProperty`. Icons are inline SVG (`ICONS` in `app.js`). The drive list is intentionally NOT shown on the main screen; archive folders are managed in `#folders-dlg`. Detail is a side drawer (`#detail`, full-screen under 860px). Cards: poster + rating chip + dot beside the name; no-poster films get a hue from the title.
- `src/updater.js` — self-update from GitHub Releases (packaged app only): `api.checkUpdate` / `api.downloadUpdate` / `api.installUpdate`, see Release below.

## Rules that must not break

- Never write, rename, move or delete anything inside the user's media folders. Scanning is read-only.
- Metadata only from OMDb and Jikan. No IMDb scraping, no IMDb dataset, no trailers/reviews/downloads, no semantic/embedding search.
- The OMDb key comes only from the `omdbKey` setting. A key inside a pasted OMDb link is ignored and never stored.
- Folder keys are (drive serial, relative path with `/`), never drive letters.
- A title with several folders or drives is one entry with many locations.
- OMDb answers HTTP 200 with `Response:"False"`; map errors to `ProviderError.kind` (`not_found`, `quota`, `bad_key`, `network`).
  `quota` and `network` stop the queue and leave the location `pending`.
- Scan classification (`scanner.js`): ignored name → skip; season token (`S01`, `Season 1`, `فصل 1`, not followed by a letter or digit)
  → one location, never opened, series name = text before the token or the parent folder; has a season child, is in `collections`,
  or has subfolders with no video and no year in its name → opened, not a location; otherwise one title (even if empty). Max depth 8,
  symlinks not followed, an unreadable folder is never marked missing.
- Never store a MyMemory quota or error text as a translation (`quotaFinished`, status 429, text starting `MYMEMORY WARNING` → `ProviderError('quota')`).
  Translations are stored per ≤450-char chunk (SHA-1 of the chunk), so quota mid-text loses nothing. Persian text is never sent.
- Episode plots come only from OMDb (series) or Jikan (anime, one request per episode, 400 ms apart). `episodes.plot` NULL = not fetched,
  `''` = source has none. Season lists that OMDb does not know are remembered under cache key `season-none:<titleId>:<n>`.
- Rescan is incremental: existing `(drive, rel_path)` rows keep status/title/pins/translations; only new folders are inserted (`syncScan` returns the count, `api.scan` returns `{scanned, added}`).
- A root with `single = 1` is one folder (one title, or a series), not a folder of titles. `scanFolder(..., { only })` keeps just that child; `syncScan` marks only that rel_path (and below) missing, never siblings.
- Collections: a folder that opens (no video of its own, or several separate movie files — `NOT_A_MOVIE` filters samples/trailers/episodes/disc parts) stores its rel path in `locations.collection` for every title under it (a series folder passes the outer collection through). `library.collectionEntries` adds one `kind: 'collection'` entry per folder with ≥2 members (All tab only). A file entry's `rel_path` is the video file; `api.openRel` opens its parent folder. `openCollection` only opens a path some stored location names as its collection.
- Attention state is computed in core (`library.attentionOf`): `ok` (no marker), `guess` (yellow dot), `problem` (red dot: pending/unmatched, empty or missing folder). An unplugged drive is NOT a problem. Collection entries are always `ok`. `search.query({query, tab, genres, attention, sort})` returns `{entries, genres, attentionCounts}`; each facet's counts honor the other facet's filter. Genres/status/sort live in the filter sheet (`#filter-dlg`), not a top chip row. Cards show the rating as a chip on the poster, no status text.
- Performance rules (measured: 100 films 24 s → 5 s): network work goes through `core/pool.js` (`api` passes `concurrency: 5`; core defaults to 1 so tests stay ordered). The queue never asks twice for the same film (in-flight map by title|year|season). Jikan is spaced by `createJikan({ minGap: 350 })`, not by callers. `openDb` sets WAL + `synchronous=NORMAL` and the `loc_twin`/`loc_title` indexes (a test checks the query plans; do not add a low-selectivity index like `locations(status)`, the planner then skips `loc_twin`). The grid asks for `getEntries({light: true})` (card fields only) and the open card for `getEntry(key)`; never send plots/cast for the whole list. Sorting uses one shared `Intl.Collator`. The fuzzy index is built on the first typed query. CSS: no `backdrop-filter` on repeated or sticky elements; cards use `content-visibility: auto`.
- Manual tags: `tags(location_id, tag NOCASE)`, one row per folder, so they survive rescans and fixes (`syncScan`/`applyFix` never touch them). An entry's `userTags` is the union over its locations (`library.js`); `core/tags.js` has `normalizeTag` (trim, collapse spaces, max 30) / `addTag` / `removeTag`. `api.addTag/removeTag(key, text)` → `{ok}` or `{ok:false, error: empty|too_long|unknown}` (collections refused); `api.getTags()` → `[{name,count}]`; `search.query({tags})` needs ALL tags, returns `tagCounts` (honors genre+status filters, and they honor tags). Light entries carry `tags` (first 2). UI: filled accent chip with tag icon (`.mine`) vs outlined gray genre; detail has the editor (`myTagsSection`), filter sheet has `#f-tags`. `removeRoot` deletes orphan tag rows.
- Copy list (copy only, never move): `core/transfer.js` (`cleanName`, `isInside`, `pickLocations`, `treeSize`, `copyTree`), wired as `api.planTransfer({keys,destDir,name})` (preview: jobs, skipped with reason, bytes; errors `bad_name|bad_dest|inside_archive|no_space|nothing`), `api.startTransfer(request, onProgress)` (re-plans itself, never trusts paths from the renderer; `busy` while one runs; progress events `{type:'copy', index, total, title, doneBytes, totalBytes}` on `api:progress`; the callback is the last argument, see `main.js`) and `api.cancelTransfer()`. Sources are only read; the target must not be inside any archive root or any source. One usable copy per movie (online, not missing/empty; prefer a drive other than the destination's), one per season of a series (copied under `<series title>/<season folder>`); jobs are ordered by source drive. Files already in the destination are skipped, never overwritten; cancel removes only the partial file it was writing. Copying is done by Node streams, not TeraCopy/robocopy (not tried on Windows). UI: cart in `state.cart` (memory only), `#copy-dlg`, header `#copy-btn`.
- Countries: `countryList` (OMDb `Country`) on every entry; `search.query({countries})` is ANY-of, returns `countryCounts`; Persian names in `COUNTRIES_FA`. Selection mode (`state.selecting`/`picked`) does bulk `addTags`/`removeTags`/cart add; tagging a collection tags every member's location, collection `userTags` = tags shared by all members; copying a collection copies each member (films inside a selected collection folder are not copied twice). `api.addDropped(paths)` adds a dropped folder/video as a `single` root (read-only), the renderer gets paths through `pathOf` (webUtils).
- Background translation: `translate.pretranslate` walks plots missing a stored translation; stops on `quota`/`network`; `api.startPretranslate/stopPretranslate`, setting `autoTranslate` (default true), started ~4 s after launch when the UI is Persian.
- Calendar (`core/calendar.js`, `api.calendar*`, `api.getAiring`): weekly reminder = title, weekday, time, next episode. `calendarTick` marks the episode done and creates the next one itself (episode+1, +7 days). Fires only while the app runs; on open the renderer shows what is due. "Airing" on a series card creates the reminder; finished series (OMDb `Year` closed range / ended) do not offer it.
- Copies: named lists persisted (`getCopyLists/saveCopyLists`), a finished copy is a `copies` row with a SHA-256 manifest. After a copy the app deep-verifies and repairs automatically; `verifyCopy(id,{deep})` (quick = exists+size, deep = rehash, source not needed), `repairCopy(id)` recopies only bad files from a usable source, `removeCopy(id)` forgets the row (never deletes files). The renderer routes `api:progress` through `progressHandlers[type]`.
- Copy speed: `core/rate.js` `createRate().sample(t, done, total)` (last 5 s window) is added to `copy` progress events as `bytesPerSec`/`etaSec` (`null` until two samples); `createApi({clock})` is injectable for tests. `main.js` takes the single-instance lock (a second launch quits and focuses the first window) and passes `version` from `package.json`; `api.getVersion()` feeds the header `#app-version`.
- Similar films: `core/similar.js` `similarTo(base, entries, {limit})` scores matched entries of the same `kind` (genre Jaccard ×4, shared director +3, shared actors +2 each up to 4, shared own tags +1.5 each up to 3, country +0.5 up to 1, year gap ≤3 +1 / ≤10 +0.5); something real (genre, director, actor or tag) must be shared; returns `{entry,key,title,score,reasons:[{type,values}]}`. `api.getSimilar(key, limit=12)` → `{ok, items}` (light entries + `score`, `reasons`). UI: `similarSection` in the detail drawer (matched, non-collection entries). Local only: no model, no network (the owner's rule: no semantic/embedding search). An AI "describe a mood" box was discussed and NOT built (needs an API key the owner can use).
- Anime recommendations: `jikan.recommendations(malId, limit)` (`/anime/{id}/recommendations`, most votes first). `api.getRecommendations(key, limit=12)` → `{ok, inArchive:[light entry + votes], outside:[{malId,title,votes,posterFile}]}` or `{ok:false, error: unknown|not_anime|not_found|network}`. Uses `titles.mal_id`; an OMDb title with genre Animation gets its MAL id from `jikan.searchAnime` only when the names match exactly (`nameKey`: lowercase letters+digits), remembered as cache `mal-of:<titleId>`. The top 25 recs are cached as `mal-rec:<malId>` (errors are not cached). In-archive match: by `mal_id`, else by `nameKey` of the title. Outside posters are downloaded to the archive posters folder as `mal<id>.jpg`. `api.openMal(id)` opens myanimelist.net/anime/<id>. UI `recommendSection` (anime only). Movies get no outside suggestions (OMDb has none; TMDB is blocked for the owner and not allowed by the metadata rule).
- Anime show only under the All tab (`kind` is `other`); there is no anime tab yet.
- The interface must not offer watched/favourite/random-pick features; the owner rejected them. **One exception, asked for by the owner (2026-11-22): delivery history.** The shop (internet café / film club) records which films each customer received (`orders`, `order_items`) and warns when a film is added to a copy list for a customer who already got it. This is shop bookkeeping, not a viewing tracker: do not add "watched", ratings by the owner, favourites or random pick on top of it.
- Quality flags: `core/quality.js` `qualityOf(name)` reads only folder names (the whole `rel_path`, so a parent folder like `Dubbed/` counts): `res` 4K/1080p/720p/480p (a number inside a title is not a resolution), `dub` (دوبله, Dub, Dubbed, دو زبانه), `sub`, `hardsub` (زیرنویس چسبیده, HardSub); `mergeQuality` takes the best resolution and any flag over an entry's folders. Entries carry `quality`; light entries carry `badges` (`4K`/`1080p`, `dub`, `sub`|`hardsub`). `search.query({quality: ['dub','sub','hardsub','hd','4k']})` needs ALL chosen flags and returns `qualityCounts`.
- Persian search: `core/persian.js` `normalizeFa` (ي/ی, ك/ک, آ/ا, ة/ۀ→ه, digits, half-space, diacritics, lowercase) is applied to a side copy of the text Fuse searches and to the query; stored text is never changed. Other names: table `aliases(location_id, alias NOCASE)` (like tags: per folder, survive rescans and fixes, removed with their root), `entry.aliases`, `api.addAlias/removeAlias(key, text)` (max 80 chars), searched with weight 3 like the title.
- Reports (`#rep-dlg`, tabs in `REPORTS` in app.js): `gaps` (`core/gaps.js` `seriesGaps`: episode numbers read from file names under each season folder vs aired OMDb/Jikan episodes; only plugged-in drives, a folder with no readable numbers is not judged), `single` (`reports.singleDrive`: titles whose present folders are all on one drive), `catalog` (`reports.catalogByGenre`: every title once under its first genre; printed through `window.print()` into `#print-area`, PDF = the print dialog), `orders`, `requests`, `wishes`.
- Backup: `core/backup.js` `exportData/importData` (JSON, format `movie-archive-backup` v1): settings (never `omdbKey`), tags and aliases keyed by (drive serial, rel path), reminders, copies with manifests, orders, requests. The archive itself is rescanned, not backed up. `api.exportBackup(file)/importBackup(file)`, file pickers `dialog:save/open` in main.js (the renderer only gets the chosen path).
- Orders and prices: a finished copy records one `orders` row (customer name, phone, note, bytes, price) with `order_items` (`ref` = imdb id, `mal:<id>` or `n:<name>|<year>`, so history survives rescans and fixes). A customer is told apart by `orders.customerKey` (letters+digits, Persian-normalised). `api.getDelivered({customer, keys})` → `{[key]: {created, orderId}}` drives the warning in the copy dialog (collections check each member). `api.getOrders({customer})`, `getCustomers`, `removeOrder` (record only). Prices: settings `pricePerGB`, `priceMovie`, `priceSeason` (0 = unset; no total shown if all are 0), `shopName`; `orders.priceOf(jobs, settings)`; the invoice is built in `#print-area` and printed with `window.print()`.
- Requests: `requests(name, key UNIQUE, count, last)`; `api.addRequest(name)` counts up on a repeat (same normalised name) and answers `inArchive` when the archive already has it (title, alias or folder name).
- Flash drives: `drives.listRemovable()` (PowerShell, DriveType 2), `drives.ejectDrive(root)` (Explorer eject verb; only a drive letter root passes `isDriveRoot`, and `api.ejectDrive` only ejects a drive that is listed as removable now). The copy dialog shows the live size and free space of the destination and refuses what will not fit (`no_space`). Not tried on real Windows hardware.
- Phone catalog: `core/catalog-server.js` (plain `node:http`, off by default, setting `phoneCatalog`, port `catalogPort` default 8787, binds 0.0.0.0) serves `/?lang=fa|en` (self-contained page from `core/catalog-page.js`, default = the `language` setting, no outside files; kind tabs, sort, genre chips, AND-token search over title + `a`, 60 cards per page, a "cannot find it? ask" box), `GET /api/films?lang=` (`catalogRow` in api.js: `{k,t,y,g,r,b,a,p,kd,s,o,d}`; `g` is translated; `a` = aliases + director + actors + the Persian words of folder names (quality words removed), never a path or drive; `kd` movie|series|anime; `s` seasons owned), `GET /poster/<key>`, `POST /api/wish` (name required, ≤200 films that exist, body ≤16 KB, 5 lists per address per 10 min → 429, answers `{ok, id}` = the reference number the customer is shown; inbox capped at 300 → 503) and `POST /api/ask` (a film the archive lacks; 20 per address per 10 min; `api` counts it in `requests` only when the archive does not already have that name, otherwise the answer lists what we have). Sent lists are stored in `wishes` (items JSON) and shown in Reports → "Customer lists from phones" (marks films that customer, by name, already received; the app polls every 15 s and shows a badge on the reports button plus a status line for a new list), one button moves them into the copy list with the customer's name. `api.startCatalog/stopCatalog/getCatalogInfo/initCatalog` (`initCatalog` runs at launch from `main.js`); the QR is a PNG data URL from the `qrcode` package (CSP allows `img-src data:`). Nothing can be changed through it except adding a `wishes` row. Windows may ask for a firewall rule the first time; not tried on a real network.

## Release (how the owner updates the app)

Same system as the owner's Music Player, adapted to Electron.

1. GitHub → Actions → CI and release → Run workflow → type the version (`0.4.1`). No tag, no version-bump commit. A tag `v0.4.1` push also works (version = tag name).
2. The release job validates the version (`N.N.N`), refuses one that already has a release (`gh release view`), writes it into `package.json` at build time (`pkg.version = process.env.VERSION`), then `electron-builder --win --publish always`. The repo's own `package.json` version only matters for dev runs; do not hand-edit it for a release. The typed version reaches the shell only through `env:` (never interpolated into `run:`).
3. `build.publish[0].releaseType` is `release`: electron-builder's default is `draft`, and the updater never sees drafts. The job has a `concurrency` group per version so a second run cannot create a second release. GitHub creates tag `v<version>` when the release is published.
4. `src/updater.js` `createUpdater`: `check()` → `dev|latest|available{version}|error` (`autoDownload=false`), `download(onProgress)` → `ready|error{message}|busy|dev` with `{type:'update', percent}` events on `api:progress`, `install()` → `quitAndInstall(true, true)` (silent, relaunch). The renderer checks 4 s after launch and every 6 h; only a found update shows anything: banner `#upd-bar` (Update / Later → percent → "Installing…", error with Try again). The header Update button is the manual check. `main.js` has no startup `checkForUpdatesAndNotify` any more.
5. The installer is not code-signed, so Windows SmartScreen shows a warning on the first install.

## Known gaps (deferred on purpose)

- Queue can overwrite a manual fix applied while that location was still `pending`.
- `collections` setting matching is exact, case-sensitive, drive-relative, `/` only.
- Persian grid cards lack `dir="auto"` on name/year.
- PowerShell output encoding may garble Persian drive labels; a failed drive listing shows no message.
- Poster file name uses the imdbID unsanitised; old poster files are not deleted after a fix.
- No `setWindowOpenHandler`/`will-navigate` guard; IPC does not check the sender; malformed `poster://` URL can throw.
- `getEntries` sends every entry over IPC on each keystroke (fine up to a few thousand titles).
- All anime seasons map to one MyAnimeList entry (shown as season 1). A category folder with a year in its name is read as a movie
  unless listed in `collections`. Persian-only folder names still go to review (the owner searches an English title by hand).
- Machine translation can be poor and its free quota is small (about 5000 chars/day, 50000 with an e-mail in settings).
- Scan (`scanFolder`) is synchronous in the main process: fast on a local disk (5000 folders ≈ 60 ms) but untested on a cold USB drive. Full-size posters stay decoded while their card is on screen (about 0.5 MB each); no thumbnails yet.
- Never run on real Windows yet: PowerShell drive listing, the NSIS build and live OMDb/Jikan are untested.
